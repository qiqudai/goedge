# Agent Sync Coverage

This note summarizes what is currently included in the agent sync payloads and
what persists on the agent side. It is based on `cdn-system/docs/agent-sync-plan.md`
and the current API/agent code.

## Global Config Sync (via /api/v1/agent/config)

### WAF (global firewall)
- Payload: `EdgeConfig.WAF` (`cdn-system/api/services/config_service.go`).
- Agent: persisted to `WorkDir/conf` and read by `lua/waf.lua`.
- Status: covered.

### Global Nginx
- Payload: `EdgeConfig.Nginx` (load from `config_items`).
- Agent: writes `WorkDir/conf/nginx.conf` + `conf/dynamic/*`, reloads Nginx.
- Status: covered.

### Resources
- Payload: `EdgeConfig.Resources`.
- Agent: `WorkDir/conf/resources.json` and `LocalResources`.
- Status: covered.

### Error Pages (from config table JSON)
- Payload: `EdgeConfig.ErrorPages`.
- Agent: `WorkDir/conf/error_pages.json` + `conf/error_pages/*.html`,
  Nginx `error_page` directives map to these files.
- Status: covered.

### Default Site Config
- Payload: `EdgeConfig.DefaultConfig`.
- Agent: `WorkDir/conf/default_config.json`.
- Status: covered.

### CC Rules/Matchers/Filters
- Payload: `EdgeConfig.CCRules`/`CCMatchers`/`CCFilters`.
- Agent: `WorkDir/conf/cc_rules.json` + matchers/filters files.
- Status: covered.

## Site-Level Sync (via /api/v1/agent/config)

- ACL rules/default action, white/black IPs, region block, CC rule id.
- Per-site limits and status (traffic_limit/conn_limit/expired/locked) are
  mapped to HTTP status + error pages in Nginx generation.
- Status: covered (see `EdgeDomain` + `blockedStatusCode()` in agent).

## Package Sync (via task)

- Payload: `package_sync` task (generated by UserPackageService).
- Agent: `WorkDir/packages/{package_id}.json` + `LocalPackages`.
- Status: covered (task-based, not part of /api/v1/agent/config).

## Log/Metric Upload (agent -> API)

- Access logs, metrics, and events are uploaded by agent; no downstream sync.
- Status: covered (unidirectional).

## Notes / Follow-ups

- Ensure any new fields added to `GlobalConfig.resources` or error pages are
  preserved in `config_service` -> `EdgeConfig` and persisted in agent.
- If new WAF sub-rules are introduced, add explicit tests and confirm they are
  exercised in `lua/waf.lua` or `resty.filter_req`.
